# People Analytics Platform

HR analytics across four domains — talent acquisition, retention, engagement, and
productivity — over a PostgreSQL warehouse, with a Claude-powered natural-language query
layer on top.

> **All data in this project is synthetic.** It is generated by
> `backend/seed/generate.py` from a fixed seed. No real employee records are involved at
> any point.

**Status:** phase 0 of 8 complete — foundation scaffolded, no metrics implemented yet.
See `docs/BUILD_PLAN.md` for the full plan and `docs/ARCHITECTURE.md` for current state.

## Stack

| Layer | Choice |
|---|---|
| Backend | FastAPI · SQLAlchemy 2.0 · Alembic · Python 3.11 |
| Database | PostgreSQL (Neon in production, docker-compose locally) |
| Metrics | SQL views + typed Python service modules |
| Frontend | Vite · React 19 · TypeScript strict · Tailwind v4 · Recharts · TanStack Query |
| AI | Claude API — `claude-sonnet-5` for NL→SQL and narrative, `claude-haiku-4-5-20251001` for bulk comment classification |
| Deploy | Backend → Render · Frontend → Vercel |

## Local setup

```bash
# 1. Database
cp .env.example .env
docker compose up -d db

# 2. Backend  (http://localhost:8000/docs)
cd backend && py -3.11 -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"
.venv/Scripts/alembic upgrade head
.venv/Scripts/python -m uvicorn app.main:app --reload

# 3. Frontend  (http://localhost:5173)
cd frontend && cp .env.example .env.local && npm install && npm run dev
```

On macOS/Linux, substitute `python3.11 -m venv .venv` and `.venv/bin/…`.

## Verification

```bash
cd backend  && .venv/Scripts/ruff check . && .venv/Scripts/python -m pytest
cd frontend && npm run build
```

Both must pass before any phase is considered done.

## Metric definitions

Every formula lives in **`docs/METRICS.md`** and is treated as a contract. Two rules
apply throughout:

- Rate metrics divide by **average headcount for the period**, never end-of-period
  headcount — the most common bug in HR analytics.
- The API returns raw numbers; all formatting happens in the frontend.

Each metric is verified twice: a pytest test against a 12-employee fixture whose expected
values were computed by hand, and an independent raw-SQL recomputation by the
`metric-verifier` subagent.

## Not in scope

- **No real authentication.** A single hardcoded demo user and bearer token.
- **Flight risk is a transparent weighted score, not a trained model** — deliberately, so
  it can be explained line by line.
- Synthetic data only; no ingestion from real HRIS/ATS systems.
